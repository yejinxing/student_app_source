# 分班编学号功能设计

- 日期：2026-11-20
- 状态：设计已确认，待编写实施计划
- 参考文件：
  - `docs/关于调整学生学号编码规则的通知.pdf`

## 1. 背景与目标

学生信息处理工具目前提供新生名册文档生成、准考证审核、照片重命名三个功能。新增“分班编学号”功能，用于把一份学生名单按专业均衡分班，并按学院学号编码规则生成学号，最后导出 Excel。

目标：

1. 优先使用 Excel 中已填写的班级数量；缺失时按每班 30–40 人的目标自动建议。
2. 在生成前提供专业级确认表，用户只需要修改班级数量，各班人数自动重算。
3. 每个专业独立分班，男女均衡、省份均衡，班内男生在前、女生在后。
4. 按官方 11 位规则生成学号（年份默认当前年、可手动修改），保留原始列，输出可直接回导其他系统。
5. 对无法落在合理班额、编码容量不足、数据缺失等情况给出明确提示。

## 2. 规则依据与样例分析

### 2.1 学号编码规则

学院文件规定学号为 11 位：

| 位次 | 含义 | 规则 |
|---|---|---|
| 1–4 | 年份代码 | 新生入学年份，4 位 |
| 5 | 层次代码 | 1 普通全日制本科；2 普通全日制专科；3 普通全日制专升本 |
| 6–7 | 系部代码 | 2 位，如 01 机械工程系、02 电气与电子工程系……09 艺术设计系 |
| 8 | 专业代码 | 同一系别下的专业流水号，1 位 |
| 9 | 班级代码 | 同一专业的班级流水号，1 位 |
| 10–11 | 学生代码 | 同一班级的学生流水号，2 位 |

示例：`20261011101` = 2026 年 / 本科 / 机械工程系 01 / 专业 1 / 1 班 / 第 01 人。

### 2.2 样例数据结论

对导入模板和导出数据逐行比对后确认：

- 两份文件均为 2513 名学生，考生号集合完全一致。
- 导出数据的学号严格符合上述 11 位规则。
- 各班人数采用“前 k−1 个班取 `ceil(总人数/班级数)`，最后一个班取剩余人数”的规则：
  - 72 人 2 班 → 36/36
  - 77 人 2 班 → 39/38
  - 100 人 3 班 → 34/34/32
  - 111 人 3 班 → 37/37/37
  - 140 人 4 班 → 35/35/35/35
- 班内顺序为：男生在前、女生在后；同性别内按省份成组；同省份内保持原始行顺序。
- 导出数据中的班级数量为事先规划值（1–4 班），不是按固定班额自动计算；少数专业（如财务管理 3 个班）实际性别分布并不完全均衡，说明样例可能经过人工调整。新功能采用确定性均衡算法，结果可能与该样例个别班级不同，但满足“男女均衡、省份均衡”的原则。
- 导入模板的“班级数量”列整列为空，因此需要“Excel 优先、缺失自动建议、用户确认”的流程。

### 2.3 隐私约束

`docs` 下的导入模板和导出数据包含真实学生信息，只作为规则参考，**不得复制进安装包、模板资产或测试夹具**。应用内置模板只包含表头。

## 3. 范围

### 3.1 本轮包含

- 新增独立“分班编学号”页面。
- 读取 `.xls` / `.xlsx` 第一个工作表，分析专业组、班级数量来源和数据质量。
- 专业级确认表：班级数量可编辑，各班人数自动计算，三级异常提醒。
- 按专业独立分班：男女配额 + 省份均衡 + 班内男生优先排序。
- 生成 11 位学号，保留原列并追加/覆盖输出列。
- 表头空模板下载。
- 单元、集成、冒烟测试与文档更新。

### 3.2 本轮不包含

- 手动把单个学生拖入/移出某个班。
- 在应用内编辑学生姓名、专业等原始数据。
- 跨专业合并分班或跨专业调剂。
- 多工作表选择（固定使用第一个非空工作表）。
- 按专业设置不同入学年份（全局共用一个年份）。
- Word/PDF 名册输出。
- 分班方案持久化或历史版本管理。
- 把方案写回原 Excel（始终生成新文件）。

### 4.2 第一步：导入学生数据

- 图例：正常（30–40）、接近边界（28–29 或 41–42）、需重点确认（低于 28 或高于 42）。
- 表格列：
  1. 院系
  2. 专业
  3. 层次
  4. 人数

  6. 各班人数
  7. 状态

- 表格纵向滚动、表头固定；提供“只看需要确认的专业”复选框，便于处理 30+ 个专业。

- 存在无效输入时生成按钮禁用，并显示原因。
- 输出列已存在时，页面提示“将覆盖已有的 班级名称/班号/班级数量/学号 列”。

### 4.4 第三步：生成结果

- 生成成功后显示输出路径，可点击用系统默认程序打开。
- 失败时保留确认表，显示具体错误，用户修改后可重试。
- 切换页面不丢失当前确认表；重新选择文件才重置。

## 5. 数据模型与校验

### 5.1 输入列

| 列名 | 必需 | 说明 |
|---|---|---|
| 姓名 | 是 | 空值报错 |
| 身份证号码 | 否 | 接受别名“身份证号”；非空重复报错 |
| 考生号 | 否 | 非空重复报错；用于辅助识别重复行 |
| 性别 | 是 | 只接受“男”“女” |
| 层次 | 否 | 用于显示；缺失时按层次代码映射 |
| 层次代码 | 是 | 1/2/3 |
| 省份 | 建议 | 缺失时黄色提示，按“未填写省份”分组参与均衡 |
| 院系名称 | 是 | 同组内必须一致 |
| 院系代码 | 是 | 数值 1–99，输出补足 2 位；不在学院文件列出的 01–09 范围时黄色提示 |
| 专业名称 | 是 | 同组内必须一致 |
| 专业代码 | 是 | 数值 1–9，输出 1 位 |
| 班级数量 | 否 | 非空时必须为 1–9 的整数；同组内应一致 |

层次代码显示映射：`1` → 本科、`2` → 专科、`3` → 专升本。输入有“层次”列时优先使用原值；缺失时使用映射值并给出 `LEVEL_NAME_FALLBACK` 警告。

### 5.2 表头处理

- 使用第一个非空行作为表头，忽略表头前的空行。
- 表头名称去除首尾空格；重复表头报错。
- `身份证号` 与 `身份证号码` 视为同一列；输出保留输入中的原始表头名称。
- 缺少必需列时直接报错，不进入确认表。
- 完全空白的行忽略；有数据但缺少必填字段的行报错并给出行号。
- 读取时使用格式化文本值（`raw: false`），身份证号、考生号、编号按字符串处理，避免 18 位数字精度丢失或前导零丢失。

### 5.3 分组键和隔离不变量

分组键：

```text
groupKey = 层次代码 + "|" + 院系代码 + "|" + 专业代码
```

`groupKey` 使用规范化后的代码（层次代码 1 位、院系代码 2 位、专业代码 1 位），分析、确认和生成三个阶段必须使用同一套规范化结果。

组内必须满足：

- 层次名称、层次代码一致。
- 院系名称、院系代码一致。
- 专业名称、专业代码一致。

硬性不变量：

1. 分班、男女配额、省份均衡、班级编号都只在组内进行；每个专业的班级编号从 1 开始。
2. 输出行的层次、院系、专业代码和名称完全沿用输入，程序不得修改学生归属。
3. 任何学生不得出现在其他专业的班级名单中。
4. 生成前后逐行比较分组键；发现变化立即中止并报错。

同专业不同层次按层次拆分成分组，因为学号第 5 位不同。

### 5.4 字段规范化

- 层次代码、院系代码、专业代码允许输入数字或数字字符串；去除首尾空格后转数值校验。
- 院系代码输出为 2 位，如 `1` → `01`。
- 专业代码输出为 1 位；`01` 规范化为 `1`。
- 层次代码输出为 1 位；`01` 规范化为 `1`。
- 班级代码为 1–9 的单个数字。
- 学号中的学生代码为 2 位，范围 01–99。

## 6. 班级数量与异常判定

### 6.1 班级人数公式

给定总人数 `N`、班级数 `k`：

```text
size = ceil(N / k)
sizes = [size, size, ..., size]   // 前 k-1 个班
last = N - size * (k - 1)
```

仅当 `last >= 1` 时该 `k` 有效；否则跳过。示例：

| N | k | 各班人数 |
|---|---:|---|
| 72 | 2 | 36 / 36 |
| 77 | 2 | 39 / 38 |
| 100 | 3 | 34 / 34 / 32 |
| 111 | 3 | 37 / 37 / 37 |
| 5 | 4 | 无效（last = −1） |
| 5 | 5 | 1 / 1 / 1 / 1 / 1 |

### 6.2 班级数量来源

按组收集“班级数量”列的非空值：

| 情况 | 初始班级数 | 来源标记 | 提示 |
|---|---|---|---|
| 全部非空且一致 | 该值 | Excel | 无 |
| 部分行填写、值一致 | 该值 | Excel（部分行填写） | 黄色：已按专业统一 |
| 出现多个不同值 | 出现次数最多的值；并列取较小值 | Excel 不一致 | 黄色：必须确认或修改 |
| 全部为空 / 无该列 | 自动建议值 | 自动建议 | 无 |
| 非整数、<1、>9 | 自动建议值 | Excel 值无效 | 红色警告：已改用自动建议，可确认或修改 |

若按上述规则选出的初始值本身无效（非整数、<1 或 >9），统一按“Excel 值无效”处理：改用自动建议并标记 `CLASS_COUNT_EXCEL_INVALID` 红色警告。

### 6.3 自动建议算法

候选 `k`：`1..min(9, N)`，且 `last >= 1`，且所有班人数 `<= 99`。

对每个候选计算偏差：

```text
deviation(size) = 30 - size    // size < 30
                  0            // 30 <= size <= 40
                  size - 40    // size > 40
```

按以下顺序取最优：

1. 最大偏差最小；
2. 总偏差最小；
3. 班级数更少（k 更小）。

典型结果：

| N | 自动建议 | 各班人数 | 状态 |
|---:|---:|---|---|
| 20 | 1 | 20 | 红 |
| 50 | 2 | 25 / 25 | 红 |
| 82 | 2 | 41 / 41 | 黄 |
| 120 | 3 | 40 / 40 / 40 | 正常（可手动改 4 班 30/30/30/30） |
| 400 | 9 | 45 × 8 / 40 | 红 |
| 891 | 9 | 99 × 9 | 红 |
| 892 | — | 无可用方案 | 错误，禁止生成 |

`892` 的原因：9 个班时首班 100 人，超过学生代码 2 位的 99 上限；且班级代码只有 1 位，无法再增加班级。提示拆分专业或调整编码规则。

### 6.4 提醒等级

| 等级 | 条件 | 页面表现 | 生成行为 |
|---|---|---|---|
| 正常 | 30–40 | 绿色徽标 | 直接生成 |
| 接近边界 | 28–29 或 41–42 | 黄色徽标 + 顶部横幅 | 直接生成 |
| 需重点确认 | <28 或 >42 | 红色徽标 + 顶部横幅 | 弹二次确认，允许继续 |
| 错误 | 确认页最终提交的班级数无效、班级人数 >99、编码不可表示 | 红色文字，生成按钮禁用 | 禁止生成 |

专业组等级取该组所有班级中最严重的等级：只要有一个班为红色，整行标红；没有红色但至少一个黄色，整行标黄。

### 6.5 Excel 提供班级数的校验

- Excel 提供的值不是 `1–9` 的整数 → 不直接采用，初始改用自动建议，并标记 `CLASS_COUNT_EXCEL_INVALID` 红色警告；用户确认或修改后可生成。
- 用户在确认页最终提交的班级数必须是 `1–9` 的整数，且 `k <= N`；否则标记 `CLASS_COUNT_INVALID`（大于 9 时标记 `CLASS_COUNT_OVERFLOW`），禁用生成。
- 任一班人数超过 99 → 标记 `CLASS_SIZE_OVERFLOW`，禁用生成，提示增加班级数；若 9 个班仍超 99，提示拆分专业。
- 红色/黄色人数提醒只提示，不阻止生成；错误阻止生成。

## 7. 均衡分班算法

### 7.1 男女配额

对每个组：

```text
N = 总人数
M = 男生数
F = 女生数
sizes = 各班人数

m_i = floor(M * sizes_i / N)          // 初始男生配额
remainder = M - sum(m_i)
按以下顺序给前 remainder 个班各加 1：
  1. 小数部分 M * sizes_i / N - m_i 从大到小
  2. sizes_i 从大到小
  3. 班号从小到大

f_i = sizes_i - m_i
```

性质：

- `sum(m_i) = M`，`sum(f_i) = F`。
- `0 <= m_i <= sizes_i`。
- 男女比例尽量贴近整体比例；无法整除时差 1。

### 7.2 省份均衡

对男女分别处理：

```text
for gender in [男, 女]:
  groups = 该性别学生按省份分组
  省份按人数从多到少排序；人数相同按首次出现顺序
  for province in groups:
    for student in province.students（保持输入顺序）:
      candidates = 该性别剩余配额 > 0 的班级
      选择 min by:
        1. 本班中该省份人数
        2. 该性别剩余配额（取负值，即配额多者优先）
        3. 班号
      分配学生；更新省份人数和剩余配额
```

约束优先级：

```text
班级人数 > 男女配额 > 省份均衡 > 输入顺序
```

极端情况下允许某班某性别为 0、某班某省份为 0；前两项必须满足。

### 7.3 班内排序

1. 男生在前，女生在后。
2. 同性别内按省份成组；省份顺序取该省份在输入中首次出现的顺序。
3. “未填写省份”排在最后。
4. 同省份内保持 Excel 原始行顺序。
5. 各班按班号 1..k 输出。
6. 整体输出按 `层次代码 → 院系代码 → 专业代码 → 班号 → 班内顺序` 排列，代码按规范化后的数值升序。

### 7.4 算法示例

- 72 人、男 60/女 12、2 个 36 人班 → 男 30/30、女 6/6；每班先排 30 名男生，再排 6 名女生。
- 50 人、2 个 25 人班 → 男女配额按比例分配；因班额 25 人为红色，生成前需二次确认。
- 120 人、男 118/女 2、3 个 40 人班 → 男 40/39/39、女 0/1/1；两名女生分到不同班，优于示例中两人都在 3 班的结果。
- 某省 5 人分 3 班 → 2/2/1，不会出现 5/0/0。

### 7.5 跨专业隔离校验

生成时：

1. 每行保存原始 `groupKey`。
2. 分班完成后逐行断言 `groupKey` 未改变。
3. 每班只从本组学生中抽取。
4. 学号中的层次/院系/专业代码必须等于该行原始代码。
5. 任一断言失败立即中止，不写输出文件。

## 8. 学号生成与导出

### 8.1 学号格式

```text
studentId = year(4) + levelCode(1) + deptCode(2) + majorCode(1) + classNo(1) + seq(2)
```

- `year`：默认当前系统年份（4 位），确认页可手动修改；必须是 4 位整数（建议 2000–2100），否则报 `INVALID_YEAR` 并禁止生成。
- `seq`：班内最终排序后的序号，从 `01` 到该班人数，补足 2 位。
- 班级名称：`${classNo}班`，如 `1班`。
- 班号：数字 1–9。
- 班级数量：最终 `k`。

示例：

| 层次 | 院系 | 专业 | 班 | 序号 | 学号 |
|---|---|---|---|---|---|
| 本科 1 | 01 | 1 | 1 | 01 | 20261011101 |
| 本科 1 | 01 | 1 | 1 | 36 | 20261011136 |
| 本科 1 | 01 | 1 | 2 | 01 | 20261011201 |
| 本科 1 | 09 | 8 | 4 | 30 | 20261098430 |

### 8.2 编号列

- 输入已有“编号”列：保留每个学生的原值，不重新生成；空值保持空值。
- 输入没有“编号”列：按输入数据行顺序生成 `1..N`，作为新列追加；完全空白的行不计数。
- 因输出按班级重排，生成的编号在输出中不连续，与样例导出一致。
- 非空“编号”重复时给出黄色提示，不阻止生成。

### 8.3 输出列

- 保留输入的全部列和列顺序。
- 目标列：`班级名称`、`班号`、`班级数量`、`学号`。
  - 已存在：原位覆盖。
  - 不存在：追加到末尾，顺序为 `编号`（仅生成时）、`班级名称`、`班号`、`班级数量`、`学号`。
- 不重命名、不删除输入列。
- 学号、编号、身份证号、考生号按文本写出，避免 Excel 自动转科学计数法或丢失前导零。
- 输出文件扩展名统一为 `.xlsx`，即使输入是 `.xls`。

### 8.4 输出文件命名

```text
<输入文件名（不含扩展名）>_分班学号_YYYYMMDD_HHmmss.xlsx
```

- 与输入文件同目录。
- 同名已存在时依次追加 `_1`、`_2`，不覆盖已有文件。
- 渲染层不能指定输出路径；路径由主进程生成并校验。

### 8.5 内置模板

- 文件：`assets/学生分班模板.xlsx`。
- 主进程通过现有 `assetPath()` 解析模板路径，兼容开发与打包环境。
- 内容：仅表头行，无数据行；表头为：
  `姓名、身份证号码、考生号、性别、层次、层次代码、省份、院系名称、院系代码、专业名称、专业代码、班级数量`
- 下载时弹出保存对话框，默认文件名 `学生分班模板.xlsx`。
- 若模板资产缺失，返回 `TEMPLATE_NOT_FOUND`，提示重新安装或更新应用。
- 模板不得包含任何真实学生数据。

## 9. 技术架构

### 9.1 业务模块

新增 `src/classAssigner/`：

| 文件 | 职责 |
|---|---|
| `index.js` | 对外 API：`analyzeWorkbook(filePath)`、`generateWorkbook({ filePath, classCounts, fingerprint })` |
| `columns.js` | 表头识别、别名、必填列、输出列原位覆盖/追加 |
| `groups.js` | 按层次+院系+专业分组、班级数量来源、组内名称一致性 |
| `classPlan.js` | 班级人数、自动班级数、提醒等级、`k=1..9` 预计算选项 |
| `assign.js` | 男女配额、省份均衡、班内排序、跨专业隔离断言 |
| `studentId.js` | 学号格式化/校验、班级名称与班号 |
| `validation.js` | 必填、代码、重复值校验，错误带 Excel 行号 |
| `excel.js` | 读取第一个非空工作表、写输出、保留原列 |

模块不依赖 Electron，只使用 `xlsx`、`fs-extra`、`path`，便于单元测试。

### 9.2 IPC

新增 `src/main/ipc/classAssignIpc.js`，全部使用 `ipcMain.handle`：

| 通道 | 输入 | 输出 |
|---|---|---|
| `select-class-assign-excel` | 无 | 文件路径或 `null` |
| `analyze-class-assign-excel` | `{ filePath }` | 工作表名、默认年份、指纹、分组摘要、班级数选项、错误/警告、已存在目标列 |
| `generate-class-assign` | `{ filePath, fingerprint, classCounts, year }` | 输出路径、结果摘要、警告 |
| `download-class-assign-template` | 无 | `{ success, path?, message?, code? }` |

统一返回结构（模板下载除外）：

```js
{ ok: true, data: { ... }, warnings: [] }
{ ok: false, error: { code, message, details? }, warnings: [] }
```

约束：

- 文件路径必须存在、是文件、扩展名为 `.xls`/`.xlsx`。
- `classCounts` 必须是普通对象，键为本次分析返回的 `groupKey`，值为 1–9 的整数；遍历时使用本次分析的 `groupKey` 白名单，忽略原型链键和未知键。
- `year` 必须是 4 位整数（建议 2000–2100）；缺失或非法返回 `INVALID_YEAR`，不使用隐式回退。
- 输出路径由主进程生成，渲染层不可指定。
- 分析结果只返回专业组摘要，不返回学生姓名/身份证等明细。
- 若 `generate` 时文件指纹与分析时不同，返回 `FILE_CHANGED`，要求重新分析。

### 9.3 预计算选项

`analyze` 为每个组返回 `k=1..min(9,N)` 的选项；无效的 `k` 也保留在列表中（`valid: false`），供 UI 显示原因。自动建议只从 `valid: true` 的选项中选择。

```js
{
  classCount: 3,
  sizes: [34, 34, 32],
  level: 'ok' | 'warn' | 'danger' | 'invalid',
  valid: true,
  reasons: []
}
```

渲染层修改班级数时直接按 `classCount` 查找选项，不重复实现班级人数公式，保证前后端一致。

### 9.6 数据流

1. 用户选择文件 → 渲染层 `invoke('analyze-class-assign-excel')`。
2. 主进程读取、校验、分组，返回摘要、默认年份和预计算选项。
3. 渲染层编辑班级数和入学年份，班级数只在本地切换选项并更新状态。
4. 用户点击生成 → 渲染层发送文件路径、指纹、最终班级数和年份。
5. 主进程重新读取、校验指纹和年份、分班、编学号、写输出。
6. 渲染层显示输出路径并提供打开操作。

### 9.7 性能与隐私

- 2513 行 / 31 个专业组在主进程内处理，预计 1 秒内完成；暂不引入 `utilityProcess`。
- `analyze` 的 IPC 载荷只包含组级摘要和最多 9 个班级数选项，不包含学生明细。
- 输出只写本地文件，不发起网络请求。
- 模板和测试夹具不含真实学生数据。

## 10. 错误与警告

### 10.1 错误（阻止分析或生成）

| 代码 | 场景 | 处理 |
|---|---|---|
| `FILE_NOT_FOUND` | 文件不存在 | 提示重新选择 |
| `FILE_TYPE_INVALID` | 非 `.xls/.xlsx` | 提示支持格式 |
| `FILE_READ_FAILED` | 文件被占用/损坏 | 显示底层原因 |
| `FILE_CHANGED` | 分析后文件被修改 | 要求重新分析 |
| `INVALID_YEAR` | 入学年份缺失或不是 4 位整数 | 标红并禁用生成 |
| `SHEET_EMPTY` | 工作表为空 | 提示无数据 |
| `HEADER_MISSING` | 缺必需列 | 列出缺失列 |
| `HEADER_DUPLICATE` | 表头重复 | 列出重复表头 |
| `REQUIRED_FIELD_MISSING` | 必填字段为空 | 列出 Excel 行号和字段 |
| `INVALID_LEVEL_CODE` | 层次代码非 1/2/3 | 列出行号 |
| `INVALID_DEPT_CODE` | 院系代码非 1–99 | 列出行号 |
| `INVALID_MAJOR_CODE` | 专业代码非 1–9 | 列出行号 |
| `INVALID_GENDER` | 性别非男/女 | 列出行号 |
| `DUPLICATE_STUDENT_NO` | 考生号重复 | 列出重复值 |
| `DUPLICATE_ID_CARD` | 身份证号重复 | 列出重复值 |
| `GROUP_NAME_CONFLICT` | 同组名称/层次不一致 | 列出冲突组和行号 |
| `CLASS_COUNT_INVALID` | 确认页最终提交的班级数为空/<1/非整数/>N | 标红并禁用生成 |
| `CLASS_SIZE_OVERFLOW` | 任一班人数 >99 | 提示增加班级数 |
| `CLASS_COUNT_OVERFLOW` | 班级数 >9，编码不可表示 | 提示减少班级数或调整编码 |
| `NO_VALID_CLASS_PLAN` | 无任何可用班级数 | 提示拆分专业/调整编码 |
| `GROUP_KEY_CHANGED` | 生成前后分组键变化 | 中止，不写文件 |
| `STUDENT_ID_DUPLICATE` | 生成学号重复 | 中止，提示数据异常 |
| `OUTPUT_WRITE_FAILED` | 输出写入失败 | 显示路径和原因 |
| `TEMPLATE_NOT_FOUND` | 分班模板资产缺失 | 提示重新安装或更新应用 |

### 10.2 警告（不阻止生成）

| 代码 | 场景 |
|---|---|
| `PROVINCE_MISSING` | 省份为空，按“未填写省份”分组 |
| `DEPT_CODE_UNKNOWN` | 院系代码不在学院文件列出的 01–09 范围，需确认是否为新设系部 |
| `LEVEL_NAME_FALLBACK` | 层次名缺失，按代码映射显示 |
| `CLASS_COUNT_EXCEL_PARTIAL` | 班级数量部分行填写 |
| `CLASS_COUNT_EXCEL_INCONSISTENT` | 同组班级数量不一致 |
| `CLASS_COUNT_EXCEL_INVALID` | Excel 提供的班级数无效，已改用自动建议 |
| `CLASS_SIZE_WARN` | 28–29 或 41–42 人 |
| `CLASS_SIZE_DANGER` | <28 或 >42 人 |
| `EXISTING_TARGET_COLUMNS` | 将覆盖已有目标列 |
| `DUPLICATE_NUMBER` | 编号列非空值重复 |

### 10.3 UI 行为

- 分析错误：确认表不渲染，错误列表显示在文件卡片下方。
- 生成错误：保留确认表，显示错误，允许修改后重试。
- 红色专业：点击生成时弹出二次确认；确认后继续。
- 黄色专业：顶部横幅提示，不弹窗。
- 所有错误/警告只显示在本地 UI，不上传。

## 14. 已确认决策

| 决策 | 结果 |
|---|---|
| 落地方式 | 独立页面 |
| 入学年份 | 默认当前系统年份，可在确认页手动修改（4 位） |
| 班级数量 | Excel 优先；缺失自动建议；确认页可改班级数，各班人数自动计算 |
| 自动建议目标 | 30–40 人/班；最大偏差最小 → 总偏差最小 → 班级数更少 |
| 提醒等级 | 正常 30–40；黄色 28–29/41–42；红色 <28 或 >42 |
| 红色行 | 二次确认后允许生成 |
| 分班原则 | 男女均衡、省份均衡、男生在前女生在后 |
| 分组 | 层次代码 + 院系代码 + 专业代码；跨专业严格隔离 |
| 导出列 | 保留原列；目标列原位覆盖或追加；编号保留或生成 |
| 模板 | 仅表头空表，随应用打包 |
| 输出文件 | 同目录、带时间戳、不覆盖旧文件 |
| 处理位置 | 主进程内联，暂不使用 utilityProcess |
